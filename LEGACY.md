# Legacy Curriculum Baseline

This file records the transition boundary between curriculum created before the maintained repository workflow and curriculum created under the current Learn • Think • Verify • Adapt process.

It is a domain record under `REPOSITORY_STANDARD.md`. It does not replace `CURRICULUM_WORKFLOW.md` or `communication-style.md`.

## 1. Purpose

Learning content and curriculum existed before the current Git-based workflow was established. That material may remain across historical sources, including Google Drive, and was not produced under the repository workflow now used by this project.

This file establishes a continuity point so new curriculum can proceed without requiring a complete reconstruction or migration of every historical artifact.

## 2. Legacy boundary

For curriculum continuity, the human-maintained baseline is considered up to date through:

- Weekly Intelligence 015;
- Learning Path 04;
- Module 04 and its completed Chapters.

Learning Path 04, Module 04 is considered completed with Weekly Intelligence 015.

These statements are the human-declared continuity baseline for future curriculum work. They do not claim that every historical Weekly Intelligence file, daily message, PDF, Learning Path, Module, or Chapter has been independently audited against the current repository standard.

## 3. Historical material

Material created through Weekly Intelligence 015 is treated as legacy material for the purpose of the maintained repository workflow.

Historical content remains useful and valid as project history. Its absence from this repository does not mean it did not exist, and this transition does not require all historical files to be copied into Git.

Historical material may be indexed, migrated, or reviewed later when there is a clear need. Such work must not silently rewrite the baseline recorded here.

## 4. Maintained workflow begins with Weekly Intelligence 016

Weekly Intelligence 016 is the first weekly cycle to be handled through the maintained repository workflow.

From Weekly Intelligence 016 onward, curriculum work must follow `CURRICULUM_WORKFLOW.md`, `communication-style.md`, and the higher-authority `REPOSITORY_STANDARD.md`.

The exact Weekly Intelligence supplied by the human must be preserved in that week's working change so the source intelligence, curriculum decision, approved daily content, and final Git history remain traceable.

## 5. Weekly Pull Request continuity

From Weekly Intelligence 016 onward, one working Pull Request should represent the complete weekly curriculum authoring cycle.

The weekly Pull Request begins by preserving the exact Weekly Intelligence input. After the curriculum structure is approved, each approved day's content is added to the same working branch and Pull Request in sequence. Earlier approved days remain frozen unless the human explicitly reopens them.

The Pull Request remains open while the week is being authored. It is reviewed as a complete weekly change before merge to `main`. This preserves one traceable review boundary from source intelligence through the completed weekly content.

## 6. Human authority

The legacy cutoff and curriculum completion state in this file are human-declared project facts used to continue the curriculum. They are not presented as the result of a complete historical audit.

The human remains the authority for reopening or correcting the legacy boundary if later evidence shows that a curriculum record needs correction.

## 7. Exclusions

This file does not define PDF generation, Google Drive publication automation, PDF visual standards, or Drive synchronization. Those responsibilities are intentionally outside this legacy record and may be established separately when their workflows are implemented.

This file also does not recreate historical morning or evening content, reconstruct missing historical artifacts, or certify that legacy material followed standards that did not yet exist.
